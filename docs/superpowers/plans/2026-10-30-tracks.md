# Tracks: follow-ups, reply classification, funnel, rejection patterns

## Context

hungry_hunt finds and scores jobs and emails a digest twice a day (live on GitHub Actions since 2026-10-29). The
owner's problem is not finding jobs but converting applications into interview calls, and the two cheapest levers
(follow up after a week, nudge a contact after five days) are forgotten without a system. "Tracks" adds the
follow-through layer so the daily routine takes 15 minutes: the digest opens with what is due today, hiring replies
are read from a Gmail label instead of being forwarded by hand, Monday's digest shows the funnel, and rejection
patterns show where applications are lost. **Hard rule from the owner: nothing is ever sent on their behalf.** The
only outbound email stays the digest; drafts are text to copy.

Tech stack: unchanged. Python 3.12, FastAPI, SQLAlchemy 2 + Alembic on Neon Postgres (SQLite locally), Jinja digest,
React 19 + Vite + TypeScript + TanStack Query, GitHub Actions. No new service.

Decisions already made with the owner: Gmail label (`hunt`) read-only via IMAP; cadence 7 / 5 / 21 days; named
contacts table; funnel in Monday's 07:00 IST digest and always on an app page.

"Unbreakable" means: every transition is a pure function with a table test; one status ladder used by the tracker
and the API; tracker re-runs are no-ops; migration reversible and tested both ways; the digest renders when Tracks
data is empty or the report fails; the tracker failing never blocks the email (`run_daily` already isolates stages).

## Pinned decisions

1. **Status ladder** in `src/hungry_hunt/tracking/actions.py`, replaces `track.ORDER`:
   `ORDER = {"skipped":0,"applied":1,"callback":2,"test":3,"interview":4,"offer":5,"ghosted":6,"rejected":7}`.
   `advance(current, event)` returns `event` iff `ORDER[event] >= ORDER.get(current,0)`; one exception: a company
   reply (`callback` or higher) lifts `ghosted`; `rejected` always wins. `applied`/`skipped` never lift `ghosted`.
2. **`Application.stage`** = furthest non-terminal status reached (`applied|callback|test|interview|offer`), because
   manual API status changes write no `tracked_mail` row; the funnel and `rejection_stage()` read it.
3. **Clocks.** Follow-up due at `max(last_event_at, followed_up_at) + follow_up_days`; "done" sets
   `followed_up_at=now`. Ghost at `last_event_at + ghost_days` (company silence only). Nudge at
   `(last_nudged_at or messaged_at) + nudge_days` while `replied_at` is null. All datetimes UTC-aware; only the
   Monday check uses IST.
4. **Label trust.** Mail from the label folder is trusted when Gmail-stamped and DKIM/DMARC-aligned; the
   `X-Forwarded-For`/ARC requirements stay for INBOX mail. `TRACK_REQUIRE_FORWARDED=false` still accepts all.
5. **One builder.** `tracking/report.py` builds a `Tracks` model used by the digest email, `GET /api/digest` and
   `GET /api/tracks`. Funnel and patterns are computed every build; the template shows them only when `monday`.
6. **Never breaks the email.** `digest.build` wraps `report.build` in try/except → `Tracks(available=False)`.
7. **No mutating GET.** Email links open app pages; mutations are POST/DELETE.
8. **Manual correction.** `POST /api/jobs/{id}/status` refuses a downgrade with 409 unless `?force=true`; the UI
   shows the reason and an "override" button. (Owner-safety addition to the agent's design.)

## Pure rules: `src/hungry_hunt/tracking/actions.py` (new)

```
ORDER, TERMINAL={"rejected","ghosted"}, ACTIVE={"applied","callback","test","interview"},
REPLIED={"callback","test","interview","offer","rejected"}, STAGE_LABEL={"screen":"resume screens","after_test":"after a test","after_interview":"after an interview"}
advance(current: str|None, event: str) -> str
stage_after(stage: str|None, status: str) -> str|None        # unchanged for TERMINAL/skipped, else max by ORDER
rejection_stage(prior_stage: str|None) -> str                # test→after_test, interview/offer→after_interview, else screen
parse_deadline(text: str, received_at: datetime) -> datetime|None   # "within N days/hours", "by|before|until|due|deadline|expires|valid until <date>", 10 date formats, year-less → received year (+1 if past), 23:59
@dataclass(frozen=True) Action(kind: "follow_up"|"nudge"|"deadline"|"ghost", job_id, contact_id, due_at, days)
due_actions(now, settings, applications, contacts) -> list[Action]   # ghost beats follow_up (elif); deadline if deadline_at >= now; sorted by due_at
draft(kind, company, title, person, days) -> str             # three fixed sentences (follow_up / nudge / deadline)
```
Tests `tests/tracking/test_actions.py`: parametrized tables for each function (advance 14 rows incl. ghost revival,
stage_after 6, rejection_stage 6, parse_deadline 7 incl. None, due_actions 8 scenarios incl. ordering).

## Risks

| Risk | Mitigation |
|---|---|
| Label missing/renamed | `select` returns NO → warn and skip, INBOX still read; tested with FakeIMAP |
| Same mail in INBOX and label | Message-ID dedupe in `fetch_recent` and again in `apply_events` |
| Timezone drift in "days since" | all stored datetimes UTC via `TZDateTime`; only the Monday gate uses IST; backfill removes null anchors |
| Neon migration | nullable adds + two plain UPDATEs; `daily.yml` runs `alembic upgrade head` before `hunt run` |
| Report failure or empty data | `Tracks()` default, try/except → `available=False`, template gates every fragment |
| Wrong classification (offer/rejected) | narrow regexes, forward-only ladder, every mail kept in `tracked_mail` for audit, `force` override in the UI |
| Late reply after ghosting | `callback`+ revives in `advance`; manual override available |
| Import-layer rule (`test_lower_layers_do_not_import_pipeline`) | `report.py` imports only config/core/db/tracking.actions; IST lives in config |
